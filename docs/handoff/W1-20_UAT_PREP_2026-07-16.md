## Hasil smoke (HTTP API riil — semua LOLOS)

Catatan bentuk API: `RegisterInput` tanpa tag JSON, jadi payload memakai nama field Go
(`LeadName`, `PhoneNumber`, `Source`). Sesi via cookie `cdps_session` dari `POST /api/v1/auth/login`.

1. **Login** — `budi@mea.co.id` (EMP-0001, Sales staff) dan `dewi@mea.co.id` (EMP-0006,
   Sales Head) → 200 + `Set-Cookie: cdps_session=...`.
2. **Registrasi lead baru** (EMP-0001, `POST /api/v1/leads`) → **201**:
   `LEAD-202607-0001` (record_status `active`) + `PRSP-202607-0001` (status `New Lead`).
   Prefix bulan `202607` = bulan berjalan WIB — verifikasi O20 live.
3. **Dedup kolaboratif M1 v2** — EMP-0006 registrasi nomor sama dengan format berbeda
   (`0812-7777-001` vs `08127777001`; NormalizePhone mencocokkan) → **201**:
   ```json
   {"attempt":{"id":"PRSP-202607-0002","lead_id":"LEAD-202607-0001","owner_employee_id":"EMP-0006","status":"New Lead"},
    "joined":true,
    "lead":{"id":"LEAD-202607-0001", ...},
    "message":"[lead juga sedang dikerjakan sales lain (Budi Santoso)]",
    "notified_owners":["EMP-0001"]}
   ```
   Attempt kedua terlampir ke lead yang SAMA (tidak ada lead duplikat, tidak ditolak).
4. **Guard same-sales** — EMP-0001 registrasi ulang nomor yang sama → **409**
   `{"message":"[anda sudah memproses lead ini]"}` (string BI baru, DECISIONS 2026-07-16;
   sebelumnya kasus ini jatuh ke 500).
5. **Notifikasi in-app** — `GET /api/v1/notifications` sebagai EMP-0001 → `unread_count: 1`:
   ```json
   {"event_type":"m1.lead.also_pursued","entity_type":"lead","entity_id":"LEAD-202607-0001",
    "deep_link":"/lead/LEAD-202607-0001","actor":"EMP-0006","read_at":null}
   ```
6. **Kalkulator pasca-O25a** — `POST /api/v1/sales/quote-preview`, Nano KOL
   (`MSV-202607-0020`, `min_floor`, PPN):
   - qty=1 → `subtotal_idr: "Rp. 5.550.000,00"` (5jt + PPN 11%). Sebelum koreksi
     `min_qty` 10→1, qty=1 akan tertagih Rp. 55.500.000,00.
   - qty=3 → `"Rp. 16.650.000,00"`.
   - `total_komisi_idr: "Rp. 0,00"` — sesuai interim O24 (komisi 0% eksplisit).
