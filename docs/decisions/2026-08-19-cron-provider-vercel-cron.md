| 2026-08-19 | **🟢 Cron provider = Vercel Cron — un-defer wiring `internal/*/tick` (Pattern A).** Keputusan pemilik mencabut penundaan 2026-08-19 (Pattern A HTTP tick, provider ditunda). Provider = **Vercel Cron**. Konsekuensi teknis: Vercel Cron hanya bisa **GET** path di deployment-nya sendiri & meng-inject `Authorization: Bearer <CRON_SECRET>` (tak bisa kirim header `x-plan-tick-secret`). Maka (1) tiap rute tick sekarang punya handler **GET** selain POST, berbagi tick yang sama; (2) gerbang rahasia dipindah ke `apps/api/src/lib/tick-auth.ts` (`tickSecretOk`) yang menerima **dua bentuk kredensial** — `x-plan-tick-secret` (curl/GitHub Actions, `PLAN_TICK_SECRET`) **dan** `Authorization: Bearer` (Vercel, cocok `PLAN_TICK_SECRET` **atau** `CRON_SECRET`). **Fail-closed dipertahankan**: kedua env unset ⇒ 401. `apps/api/vercel.json` mendaftar **3 job** (UTC): `plan` harian `30 17 * * *` (00:30 WIB), `health` bulanan `0 1 1 * *` (tgl 1, 08:00 WIB), `performance` bulanan `15 1 1 * *` (tgl 1, 08:15 WIB — stagger 15′ dari health). **Jadwal bulanan sengaja jatuh pada tgl 1 di BOTH WIB & UTC** (closed-month diturunkan WIB O20; fire 17:xx UTC hari terakhir bulan = jebakan geser-hari → bulan salah). **`penugasan` TIDAK di `vercel.json`** — sudah `pg_cron` live (`0 0 * * *` UTC = 07:00 WIB); rutenya tetap dukung GET+Bearer agar bisa dipindah ke Vercel nanti tanpa ubah kode (drop pg_cron + tambah entri). **Aksi pemilik (deploy):** set env `CRON_SECRET` di project Vercel `agency-app-api` (nilai = `PLAN_TICK_SECRET` bila ingin satu rahasia); pastikan **Vercel Pro** (3 cron > batas Hobby 2 & Hobby harian-only); konfirmasi Root Directory project = `apps/api`. api **379** hijau (+20 tick). | Pemilik (Yohan) 2026-08-19 |
