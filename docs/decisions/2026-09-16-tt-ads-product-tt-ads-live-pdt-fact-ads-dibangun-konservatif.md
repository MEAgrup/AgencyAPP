| 2026-09-16 | **`tt_ads_product`/`tt_ads_live` → `pdt_fact_ads` dibangun KONSERVATIF, TANPA sample file asli.** Setelah "video" (#412) merge, pemilik memilih lanjut bagian laporan "iklan" berikutnya — investigasi menemukan asimetri KEBALIKAN dari "video": Shopee lengkap (`pdt_fact_ads`, sudah dipakai `rakitInputSkorShopee`), TikTok NOL — `tt_ads_product`/`tt_ads_live` terdaftar sbg modul parser (`PDT_MODULES`) tapi NOL baris pernah ditulis sejak lahir, walau `rakitInputSkorTiktok`'s dimensi `ads` SUDAH query siap sedia menunggu data. Diajukan lewat `AskUserQuestion`: (a) iklan Shopee-only ringkas — mirror "video"; (b) bangun writer `tt_ads_product`/`tt_ads_live` dulu, baru lanjut laporan "iklan" kedua platform; (c) lewati iklan sepenuhnya. **Pemilik memilih (b)**. Riset lanjutan (agen dedicated) menemukan gap LEBIH BERAT dari modul manapun sesi ini: (1) **NOL sample file asli** untuk kedua modul — SETIAP modul `pdt_fact_ads` lain (shopee_ads_cpc/search/live) selalu mengutip sample nyata sebelum dibangun; (2) `tt_ads_product` TIDAK punya kolom ROI/efektivitas di whitelist SAMA SEKALI — mesin lama (`report/metrik.ts` `adsReport()`) menurunkan `roas = Pendapatan Kotor ÷ Biaya` untuk KEDUA sisi, bahkan MENGABAIKAN kolom `ROI` mentah `tt_ads_live` yang memang ada di whitelist; (3) komentar skema migrasi G1-01 (`pdt_fact_ads.content_id`) menyiratkan `tt_ads_product` seharusnya mengisi FK itu via `ID video` — tapi NOL kode PDT manapun pernah melakukan lookup FK semacam itu, dan kesalahan SERUPA sudah terjadi (`shopee_ads_cpc` disangka bisa lookup `sku_id` dari `Kode Produk`, TERNYATA salah — `G1-09-2BII-ADS-CPC-SKU`). Diajukan opsi KEDUA lewat `AskUserQuestion`: (a) bangun konservatif — `roas` diturunkan (konsisten legacy, BUKAN tebakan baru), `sku_id`/`content_id` SELALU `null` (pola sama `shopee_ads_search`/`live`, menghindari FK lookup belum terverifikasi), dicatat eksplisit sebagai asumsi-tanpa-sample; (b) tunda writer ini, minta sample dulu; (c) lewati, kerjakan section lain. **Pemilik memilih (a)**. Dibangun: `ekstrakBarisTtAdsProduct`/`ekstrakBarisTtAdsLive` (`packages/core/src/pdt/fakta.ts`) — hanya `ID Campaign`→`kampanye_id`, `Biaya`→`biaya`, `Pesanan SKU`→`pesanan_sku`, `Pendapatan kotor`→`gmv` yang diekstrak (kolom skema nyata); `ID produk`/`ID video`/`Akun TikTok`/`Nama LIVE`/`Biaya per pesanan`/`ROI` mentah TIDAK diekstrak (nol kolom skema `pdt_fact_ads` untuk yang pertama tiga, `roas` diturunkan bukan dibaca untuk yang terakhir) — `parsePdtAngka(v, true)` konvensi Ads Manager, sesuai komentar eksplisit legacy untuk jenis file ini. `commitUploadBatch`/`reparsePdtBatch` (`packages/domain/src/pdt.ts`) menulis KEDUA modul lewat replace-on-recommit (delete-then-insert, sama alasan `shopee_ads_live`: `sku_id`/`content_id` NULL membuat `ON CONFLICT` tidak aman). **Nol perubahan** ke `rakitInputSkorTiktok`'s dimensi `ads` — query itu SUDAH benar sejak ditulis (dibuktikan tes lama pakai insert mentah), cuma menunggu jalur data nyata; dimensi `ads` TikTok kini otomatis terisi begitu klien upload file asli. **Nol migrasi baru.** Diverifikasi (DB lokal rebuild bersih, 251 migrasi — jalankan SEQUENTIAL, bukan paralel, supaya bebas kontensi DB): `@cdps/core` 1360/1360 (naik dari 1349, 11 tes baru `ekstrakBarisTtAdsProduct`/`Live`); `@cdps/domain` 2737/2737 (1 skip, nol gagal, naik dari 2733, 5 tes baru `commitUploadBatch`: satu baris per kampanye, replace-on-recommit, roas diturunkan bukan ROI mentah, dua sumber tidak saling menimpa); `@cdps/db` 107/107; `@cdps/api` 636/638 (2 skip, tidak berubah — bagian laporan "iklan" belum dibangun, nol perubahan wire/route sesi ini); typecheck bersih `core`/`domain`/`api`/`web-internal`, lint `@cdps/api` bersih; `npm run build` `web-internal` sukses.
