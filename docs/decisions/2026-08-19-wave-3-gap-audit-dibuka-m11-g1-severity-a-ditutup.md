| 2026-08-19 | **🟢 Wave 3 gap-audit DIBUKA + M11-G1 (Severity A) DITUTUP — gate Blocking-Dependency di jalur roll-up kini DEFER, bukan throw.** Audit PRD-vs-implementasi 6 modul Wave 3 (M2/M3/M11/M13/M14/M15) — semua sudah di-port saat cutover tapi belum pernah gap-audit — didokumentasikan di `docs/backlog/WAVE3_GAP_AUDIT.md`. Temuan Severity-A satu-satunya: **M11-G1.** Guard gate `board.validateBriefApproval` dipanggil telanjang di **dua** jalur roll-up (`task.ts recomputeBriefRollup` Creative/M12, `kol.ts recomputeBriefRollup` KOL/M9); ia melempar `board.ConflictError` yang, tanpa try/catch, keluar dari roll-up dan me-rollback **seluruh** transaksi `withTransaction` — termasuk transisi child (Asset `approveAsset`/Booking `passQC`) pemicu. Akibat: meng-approve Asset/Booking **terakhir** dari Brief yang menjadi Target Blocking-Dependency yang Source-nya belum `[Approved]` **gagal total** dengan pesan gate, bukan cuma menahan transisi ke gate. Ini melanggar **§2 Rule 7** ("PIC tetap boleh lanjut kerja di Brief itu — yang ditolak sistem cuma transisi ke gate yang terkunci … bukan seluruh aktivitas Brief"), menyimpang dari **Go oracle** (`module12_task/rollup.go` + `module9_kol/rollup.go`: `errors.As(err,&BlockedError) → return nil`, hanya BlockedError yang defer, error lain propagate), dan membalik **keputusan W3-M11-C1** (2026-07-17: "RecomputeBriefRollup **DEFER diam** — brief tetap [In Review], transisi asset pemicu tetap commit"). **Fix:** di kedua roll-up caller, bungkus panggilan gate `try { validateBriefApproval } catch (e) { if (e instanceof board.ConflictError) return; throw e }` (import `ConflictError as BoardConflictError from './board'` — hati-hati: `task.ts`/`kol.ts` punya `ConflictError` lokal sendiri, jadi HARUS tangkap kelas board). DEFER = Brief tetap `[In Review]`, child transition (sudah diterapkan lebih awal di tx yang sama) tetap commit, pulih otomatis pada event Asset berikutnya atau approve AM eksplisit. **Jalur AM eksplisit `account.ts driveReviewEdge`/`approveBrief` TETAP throw** — di sana surfacing pesan gate ke AM memang benar (tak diubah). **Tes (M11-G2):** `board.test.ts` "Blocking gate DEFERS on the roll-up path" — Creative (`creative.approveAsset`) + KOL (`kol.passQC`) — assert child commit `[Approved]`/`[QC Passed]`, Brief parkir `[In Review]`, lalu approve Source memuaskan dependency (notif sekali) + approve Target `[Approved]`; **terbukti GAGAL tanpa fix** (kedua test melempar `BoardConflictError` keluar roll-up). **Bukti:** board 18 · task 19 · kol 23 · creative 28 = 88 domain hijau; 6 suite Wave 3 = 102 hijau; typecheck domain bersih (selain TS5101 baseUrl pra-ada); nol migrasi/prefix/mesin/event baru; `route-parity` `KNOWN_GAPS` tetap kosong. | Bug correctness murni: satu operasi normal (approve Asset/Booking terakhir dari Brief yang jadi Target dependency) mengembalikan error alih-alih berhasil, mengunci "seluruh aktivitas Brief" yang justru dilarang §2 Rule 7.
