| 2026-08-31 | **🔴 BUG PRODUKSI DITEMUKAN & DITAMBAL — `import_employee_credentials()` melahirkan `auth.users.email_change = NULL`, menyebabkan login 500 Internal Server Error untuk SETIAP akun baru yang diprovisikan lewat fungsi itu (sync HRIS maupun manual).** Ditemukan saat memprovisikan akun trial produksi (`trial.renewal@mea.co.id`, employee_id `9900000099`, dibuat untuk pemilik mencoba fitur Renewal langsung di production) — login pertama menjawab "internal server error". Diagnosis: `email_change` (kolom internal GoTrue) TIDAK punya DEFAULT `''` di `auth.users` (beda dari `confirmation_token`/`recovery_token`/dst yang semuanya default `''`), dan `import_employee_credentials()` (`20260723071013_supabase_auth.sql`) tidak pernah menyebutnya di INSERT — jadi baris lahir dengan NULL, dan GoTrue menolak setiap request yang membaca baris itu (scan ke string Go non-nullable). **Dampak lebih luas dari akun trial ini saja**: diverifikasi langsung ke live, SATU karyawan RIIL (`2504240539`, `arisandhyyy@gmail.com`) sudah punya baris `auth.users.email_change IS NULL` yang identik — kemungkinan besar inilah akar "banyak masalah login produksi" yang pemilik laporkan sebelumnya (BUKAN rotasi kredensial database seperti dugaan awal pemilik — sesi ini tidak menyentuh `DATABASE_URL`/service-role key/connection string apa pun). **Perbaikan**: migrasi `20260902040000_fix_import_employee_credentials_email_change.sql` — `CREATE OR REPLACE FUNCTION` menambah SATU kolom (`email_change`, nilai `''`) ke INSERT `auth.users`, plus backstop `UPDATE auth.users SET email_change='' WHERE email_change IS NULL` (guard `to_regclass('auth.users')`, no-op di CI/lokal tanpa schema `auth`) yang menyapu baris NULL manapun yang tersisa. Kedua baris NULL yang ditemukan (akun trial + `2504240539`) sudah diperbaiki manual di live SEBELUM migrasi ini diterapkan (`UPDATE` langsung), lalu migrasi diterapkan untuk mencegah bug yang sama lahir lagi.
