| 2026-11-03 | **AMANDEMEN BRIDGE FASE 1 — order MSDPS→CDPS kini dikirim OTOMATIS sejak pembayaran PERTAMA (DP pun cukup); kontrak v1 TIDAK berubah.** (1) **Pemicu otomatis di sisi MSDPS** (migrasi MSDPS `0377_bridge_cdps_auto.sql`, PR `MEAGO_MSDPS#56`, live production 2026-11-04): begitu Finance MSDPS memverifikasi pembayaran pertama (`transactions.released_to_account_at` terisi), order diantre ke `POST /api/v1/internal/bridge/orders` tanpa BD menekan "Teruskan ke CDPS". Pilihan layanan CDPS diisi BD saat deal didaftarkan (atau "Tidak perlu CDPS"). (2) **DP cukup.** `attestation.diverifikasi_pada` = verifikasi pembayaran PERTAMA (bisa DP); `attestation.nilai` tetap **total kontrak**, bukan yang sudah dibayar. Gerbang D4+D13 tidak melemah: tetap hanya `Berbayar` + atestasi wajib, dan CDPS tetap menolak payload tanpa `diverifikasi_pada` untuk aktor mana pun. (3) **Info DP di `lines[].catatan`, nol kunci baru, `payload_versi` tetap 1.** MSDPS menempelkan `"[Pembayaran klien saat diteruskan: DP 30% — Rp 4.500.000 dari Rp 15.000.000]"` atau `"[Pembayaran klien: LUNAS 100% — Rp 15.000.000]"` di ujung setiap catatan (dipisah satu spasi dari catatan asli; berdiri sendiri bila catatan asli kosong). Persen dibulatkan ke bawah 1 desimal, koma desimal. Ini SNAPSHOT saat diantre — pelunasan berikutnya tidak dikirim ulang (satu arah, satu order per deal, `Idempotency-Key` `<DEAL>:1`). (4) **Validator CDPS diverifikasi, tidak diubah:** `parsePayloadV1` hanya men-trim `catatan`, `external_orders.payload` adalah `jsonb` tanpa batas panjang, tidak ada CHECK/zod pada `catatan` — catatan 500 karakter + ringkasan berisi `— % [ ] ,` diterima `[Masuk]` (tes `bridge.test.ts` + `internal/bridge/orders/route.test.ts`, mem-POST fixture v1 lewat handler route sebenarnya). (5) **Tampilan antrean:** `bridge.ringkasanPembayaranOrder` mem-parse ringkasan secara toleran dari payload MENTAH (pola tak cocok / order lama ⇒ `null`, tidak pernah melempar) dan menurunkannya sebagai field read-only `pembayaran` pada `BridgeOrderSummary` (wire `pembayaran: {status, persen, dibayar, total, teks} \| null`). `/bridge/inbox` dan detail menampilkan badge "DP x%" (kuning) / "Lunas" (hijau) + nominal di tooltip. Payload tersimpan tidak disentuh; tidak ada kolom baru. (6) **Pemetaan `Live Stream`: BELUM ADA di production** (`external_service_map` CDPS SG 2026-11-04: Account, Ads, Creative, Store Operation, KOL-Non-Roster — masing-masing ke MSV khusus "Bridge MEAGO — X" seharga Rp 0, `MSV-202609-0002…0006`). Tidak ada MSV "Bridge MEAGO — Live Stream"; MSV Live Streaming yang ada adalah paket jual agency (mis. `MSV-202607-0022`, `MSV-202608-0034…0036`), bukan pola bridge. Isi Master Service List = keputusan bisnis, jadi TIDAK dibuat di PR ini; order berbaris `Live Stream` akan gagal accept dengan `[layanan MEAGO belum dipetakan ke Master Service List]` sampai pemilik memutuskan. (7) **Kebijakan accept untuk order DP: MENUNGGU KEPUTUSAN PEMILIK** — `open/bridge-kebijakan-accept-order-dp.md`. Sampai diputuskan, perilaku tetap: DP hanya informasi, accept berjalan seperti biasa. | Bridge Fase 1 dirancang dengan pemicu manual sesudah pembayaran terverifikasi; MSDPS mempercepatnya supaya eksekusi agency bisa mulai saat klien baru DP. Menaruh info DP di `catatan` (bukan kunci baru) menjaga kontrak v1 + fixture bersama tetap identik di kedua repo — tidak ada amandemen kontrak, tidak ada drift. Trade-off: info pembayaran berupa teks manusia, jadi parser CDPS sengaja toleran dan hasilnya hanya tampilan, bukan dasar keputusan otomatis. Bila nanti persen terbayar perlu disimpan/diikuti (follow-up Finance, callback pelunasan), itu kolom baru / Fase 2 — diajukan terpisah. | Yohan, 2026-11-04 (handoff MSDPS→CDPS 0377; poin 2 & 4 menunggu keputusan) |
