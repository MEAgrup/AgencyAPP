| 2026-08-27 | **🟢 Lanjutan baris di bawah (fix `plan_tier` di `close()`, sesi yang sama): pemilik memutuskan MEMBIARKAN 2 baris produksi (`SVC-202608-0010`/`0011`) tetap `tanpa_plan` — tapi minta halamannya tetap bisa lanjut ke Strategi. Root cause kedua ditemukan: `redecideGate` (jalur eskalasi Rule 11) WAJIB ada baris `service_plan_gate` untuk dijalankan, dan `decideGate` (jalur G-B pertama) menolak MENTAH-MENTAH tier terkunci — jadi untuk Service yang lahir `tanpa_plan` TANPA baris gate sama sekali (persis kasus kedua baris ini), tidak ada pintu apa pun menuju Strategi, di kode maupun di UI.** Pemilik ditanya: koreksi data langsung, atau biarkan data + pastikan halaman punya jalur maju — **pemilik memilih membiarkan data, minta jalur majunya dipastikan ada**. Investigasi PRD (`CDPS_Module6C_Plan_Gate_Satuan.md` §5 Rule 11): *"Escalation is always available. A service running Tanpa Plan (**either by catalog or by AM decision**) can be escalated to Plan-gated at any time."* — klausa "either by catalog" itu eksplisit mencakup persis situasi ini (tier terkunci, belum pernah ada keputusan G-B apa pun), tapi `redecideGate` (satu-satunya jalur eskalasi yang ada) mensyaratkan baris `service_plan_gate` sudah ada (`throw MSG_GATE_MISSING` kalau belum), sementara `decideGate` (satu-satunya jalur yang bisa MEMBUAT baris pertama) menolak SEMUA tier terkunci tanpa pengecualian (Rule 1) — celah murni di antara dua fungsi, PRD Rule 11 tidak pernah terimplementasi untuk kasus "belum pernah ada gate row". **Yang diubah:** (a) `packages/domain/src/plangate.ts` `decideGate` — guard tier dilonggarkan SATU arah saja: `svc.tier === 'tanpa_plan' && input.keputusanAm === 'butuh_plan'` (`isLockedTanpaPlanEscalation`) kini lolos meski bukan `ditentukan_am`; arah sebaliknya (tier terkunci "memutuskan" tetap Tanpa Plan) tetap ditolak `MSG_TIER_LOCKED` — tidak menyentuh apa pun untuk `plan_wajib`. Sisa logika `decideGate` (hitung rekomendasi, simpan pemicu, buka/gabung Plan Satuan, audit log) dipakai apa adanya — tidak ada fungsi baru, murni pelonggaran satu baris `if`. (b) `web-internal/src/components/PlanGatePanel.tsx` — form G-B (sebelumnya hanya tampil untuk `tier_katalog==='ditentukan_am'`) sekarang juga tampil untuk `tier_katalog==='tanpa_plan'` tanpa baris gate (`canEscalateLockedTier`), dengan framing "Eskalasi Rule 11" (bukan "Keputusan AM" netral): keputusan dikunci otomatis ke `butuh_plan` (dropdown diganti label tetap "Eskalasi ke Butuh Plan"), tombol submit berbunyi "Eskalasi jadi Butuh Plan". Sisa form (GA konteks, GB-1/2 rekomendasi live, GB-5 alasan kondisional, GB-7 tinjau ulang) dipakai ulang persis sama — tidak ada form kedua.
