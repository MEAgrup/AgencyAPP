| O45 | **Invariant lokal secara STRUKTURAL tidak bisa melihat grant yang bocor di live — `public` di Supabase punya DEFAULT PRIVILEGES yang tidak ada di Postgres bare.** Ditemukan 2026-07-29 saat memverifikasi back-port `rls_harden_execute_surface`: `service_role` punya EXECUTE pada `private.jwt_owns_*` di live tapi tidak di build lokal, padahal SQL-nya identik. Sebabnya bukan drift — `pg_default_acl` live memberi EXECUTE ke **`anon, authenticated, service_role`** untuk setiap fungsi baru di `public` (dua grantor: `postgres` & `supabase_admin`), jadi fungsi lahir dengan grant itu dan hanya hilang bila migrasi **secara eksplisit** me-REVOKE. Postgres bare tidak punya default itu, jadi `supabase/tests/rls_checks.sql` **tidak akan pernah** gagal karena REVOKE yang lupa ditulis — CI hijau sementara produksi terbuka. **Dampak saat ini: NOL.** Diaudit langsung di live — 11 fungsi `public` bisa dipanggil `anon`, dan **nol** di antaranya `SECURITY DEFINER`, jadi semuanya jalan dengan hak pemanggil dan RLS tetap berlaku; 7 di antaranya cuma membaca klaim JWT pemanggil sendiri (`jwt_*`, mengembalikan null/false untuk anon), 2 fungsi trigger, 2 utilitas WIB murni-hitung. Satu-satunya yang menulis (`mark_notification_read`) `SECURITY INVOKER` sehingga tunduk pada RLS+grant `notifications`. Advisor Supabase juga nol temuan. **Yang perlu diputuskan:** apakah menambah cek paritas-grant yang menembak live (mis. langkah CI/ronde UAT ber-service-role yang menegaskan set fungsi `anon`-executable = allow-list), atau menerima bahwa kelas cacat ini hanya tertangkap advisor + review manual. Yang **tidak** boleh dilakukan: menganggap invariant lokal hijau sebagai bukti permukaan EXECUTE produksi aman. | Keputusan pemilik/head dev — cakupan gate keamanan | **Tidak** memblokir cutover (dampak terukur nol), tapi memblokir klaim "invariant menutupi permukaan EXECUTE" |
