| 2026-08-26 | **🟢 QA `/account`: added the `Strategi (STRG-)` queue — SPV/Head of Account had no page listing submitted M6A Strategi versions to approve.** Report (Nerissa): filed `STRG-202608-0001` (submitted, `Diajukan`) and asked where Head Account approves it, because `/account`'s "Strategy & Plan" section only showed rows like `STR-202608-0002` — the OLD `STR-`/`strategy_plans` entity (M6 §4), not the new one. Root cause, confirmed by reading `packages/domain/src/strategi.ts` and `docs/handoff/HANDOFF_M6ABC_SESI31.md` §4 item 7: `STR-` was deliberately kept alive ("jangan matikan jalur STR- sebelum UI web-internal pindah") because `/account` never migrated, and `account.listStrategies` only ever queried `strategy_plans`. Nothing queried the newer `strategi` table across clients — `listStrategiForService` exists but is scoped to one Service, and `strategi.ts`'s own module header states plainly that M6A "emits no notifications" (the four events await the v2 catalog sign-off, O55), so a submitted `STRG-` version was invisible both ways: no notification, and no queue page. The approve action itself (`approveStrategi`, `GET/PUT /strategi/{id}`, the "Setujui" button on `/account/strategi/{id}`) was already correct and reachable — only the read model that lets someone find the ID was missing, the same class of gap as the 2026-08-05 Account-queue entry below. **Fix:** new `strategi.listStrategiQueue(sql, actor)` (`packages/domain/src/strategi.ts`) — same visibility as `account.listStrategies` (Account lead/OD/Director see all clients, an Account-staff AM sees only contracts they own, everyone else `ForbiddenError`) — returning a lightweight `StrategiQueueRow` (id, contract/client id + toko, `versi_no`, `status`, `growth_thesis` as the STRG- analogue of the old free-text `objective`, the contract window, `diajukan_pada`); `GET /api/v1/strategi` (`apps/api/src/app/api/v1/strategi/route.ts`) + `strategiQueueRowToWire`; FE `listStrategiQueue()` (`web-internal/src/lib/strategi.ts`) and a new "Strategi (STRG-)" section on `/account` (`Semua`/`Menunggu Persetujuan` tabs, links to `/account/strategi/{id}` where "Setujui" already lives) placed under the existing "Strategy & Plan" section, which now also carries a one-line note that `STR-` is the old path and points at the new section — so the confusion in the report (which queue is which) cannot recur. `STR-` itself is untouched: retiring it is still a separate decision (SESI31), not this one. No migration, no schema change — a new read-only query + route + FE section. Tests: 2 new `packages/domain` integration tests (visibility scoping; carries client/contract/status/`diajukan_pada`), `shape-parity`/`route-parity`/`gate-reachability` green (`StrategiQueueRowWire` registered), domain 1466, apps/api 383, web-internal 361 all green, `next build` OK, `KNOWN_GAPS` unchanged (empty). | The read-model gap (queue missing) and the notification gap (catalog not signed off, O55) are two different problems with two different owners — closing the queue does not require or presume the v2 catalog decision, so it was fixed alone rather than bundled with a notification change nobody had signed off on. | Investigasi & perbaikan sesi ini, laporan Pemilik (nerissa.arv@meagency.co.id) 2026-08-26 |
