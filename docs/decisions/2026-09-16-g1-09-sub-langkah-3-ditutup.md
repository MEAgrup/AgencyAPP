| 2026-09-16 | **G1-09 sub-langkah 3 DITUTUP — halaman upload AM (`/account/pdt/upload`) dibangun; `GET /account/pdt/batches` (riwayat + status paket) ditutup sekalian.** Verifikasi lapangan (prioritas #2 sesi ini, per instruksi pemilik) menemukan klaim status lama TIDAK akurat: `preview`/`upload-url`/`batches` (POST) sudah lengkap sebagai kontrak API sejak sub-langkah 2a/2b, tapi `web-internal/src/lib/pdt.ts` hanya membawa TIPE (nol fungsi pemanggil), dan `find web-internal/src/app -ipath "*pdt*"` hanya menemukan `account/pdt/laporan` + `pdt/benchmark` — nol halaman upload sama sekali. Wire `PdtBatchRingkasWire`/`pdtBatchRingkasToWire` terdaftar `WIRE_TO_FE` (`shape-parity.test.ts`). **Bug ditemukan+diperbaiki lewat tes ROUTE (bukan tes domain)**: `pdt_upload_batch.id`/`client_platform_id` (`bigint`) dikembalikan driver `postgres` sebagai STRING (pencegahan presisi — pola SAMA `Number(r.gmv_30d)` di `productexchange-m3.ts`), nol konversi awal menghasilkan wire `client_platform_id: "626"` (string) bukan `626` (number); tes `listRiwayatBatchPdt` LANGSUNG (`packages/domain/src/pdt.test.ts`) SEMPAT lolos PALSU karena fixture (`insertBatchRow`/`insertClientPlatform`) dan kolom yang dibaca sama-sama string tak terkonversi (string==string) — JSON round-trip di tes route (`apps/api`) yang membongkarnya. Diperbaiki: `Number(r.id)`/`Number(r.client_platform_id)` di `listRiwayatBatchPdt`, fixture tes disamakan. **Sengaja BELUM dibangun (dicatat, bukan terlewat)**: endpoint konfirmasi identitas satu-kali AM (Rule 2/4, `usulkan_ikat` → `client_platforms.shop_id`/`akun_konten_toko` terikat permanen) — dicatat terbuka sejak sub-langkah 2a, MASIH terbuka. Batch `identitas_belum_terikat` tetap tersimpan (bisa direparse nanti via `G1-11`), halaman menampilkan usulan sistem + catatan eksplisit bahwa konfirmasi belum tersedia di UI.
